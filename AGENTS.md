# Project rules

Portfolio site for Adriano Matoba Lipski. Product spec: `docs/features-specification.md`. Design system: `docs/visual-identity.md`. Feature plans: `docs/homepage-plan.md` (done), `docs/projects-plan.md` (done), `docs/delivery-plan.md` (done; runbook in `docs/operations.md`), `docs/lab-plan.md` (done). Remaining content work is tracked in `docs/prepublish-checklist.md`.

**Keep this file current.** When a convention changes or you hit a gotcha that would trip the next agent, update this file in the same change. An outdated AGENTS.md is worse than none.

## Workflow

- **Never commit or push.** The owner reviews and commits every step. Work in steps that can be reviewed. At the end of each step, stop, list the changed files with a one-line summary each, and suggest a commit message. Then wait to be told to continue.
- **TDD, vertical slices.** One failing test → minimal code to pass → repeat. Don't write all the tests first. Unit and component tests live next to their source as `*.test.ts(x)` (Vitest). End-to-end tests live in `e2e/*.spec.ts` (Playwright). Test behavior through public interfaces. Agree the test seams with the owner before testing a new area.
- **Definition of green:** `npm run check` (lint + typecheck + format check + unit tests), then `npm run build` and `npm run test:e2e` when routes or rendering change.
- **Docs stay in sync.** After each step, update `README.md` (and any doc in `docs/` the step affects) so a newcomer can understand, run and contribute.

## Code conventions

- **KISS, but generalize when it's cheap.** If a component, handler or helper can serve more than one scenario without bending its core, make it generic (e.g. one `ButtonLink` with variants, not three buttons). Don't add speculative options.
- **Comments:** minimal. Document exported functions and components with a short docstring (`/** ... */`). Avoid inline comments unless the _why_ isn't obvious from the code. Longer explanations go in `README.md`.
- **Server components by default.** Add `'use client'` only for interactivity, theme or browser APIs, and keep client islands small.
- **Colors only via semantic tokens** (`bg-surface`, `text-muted`, `border-border`, ...) defined in `src/app/globals.css`. No raw hex in components. The only exceptions are `ImageResponse` files (`opengraph-image.tsx`, `icon.tsx`), where CSS variables don't exist, and technology logo brand colours, which come from the `simple-icons` data through `src/lib/tech-icons.ts` (never typed by hand).
- **Content is data.** Copy, links, projects, skills and pipeline stages live in `src/content/` and `src/lib/site-config.ts`, never inline in components. Unreviewed content carries `// TODO(content):` and is listed in `docs/prepublish-checklist.md`.
- **No hard-coded interface text.** Every visible or accessible string (labels, `aria-label`, captions, sentences) comes from `src/i18n/messages/` or from a `Localized` content field, read through the content file's `getX(locale)` accessor. Ids, URLs, commands, workflow excerpts and terminal output stay literal.
- **How components get the locale:**
  - Pages and layouts call `getLocale()`.
  - Server components, and components without a directive, take a `locale` prop.
  - Client components use `useLocale()` / `useMessages()`.
  - A link to another language passes `locale` to `AppLink` (see `LanguageSwitch`).
  - Don't call `getLocale()` in a component that `global-not-found.tsx` renders: that page is outside `[lang]`, so it has no root params.
- **Never render empty or placeholder links.** Validate through `src/lib/links.ts` helpers.
- **Accessibility is a requirement:** semantic HTML, one `h1` per page, visible focus, keyboard support, state never shown by color alone, and `prefers-reduced-motion` respected.
- **Imports:** use the `@/` alias (maps to `src/`).
- Formatting is Prettier with the Tailwind class-sorting plugin. Run `npm run format`.

## Environment gotchas

- The repo lives in WSL. Run npm/node from inside WSL (`wsl.exe -d Ubuntu -- bash -ic 'cd ~/adriano/projetos/portfolio && ...'`). `-i` is needed so nvm loads. `node_modules` contains Linux-native binaries, so Windows node won't work.
- On some networks a TLS-intercepting proxy blocks `npx playwright install` (`SELF_SIGNED_CERT_IN_CHAIN`); npm and Google Fonts are unaffected. Install from another network or set `NODE_EXTRA_CA_CERTS`. Chromium is currently installed in `~/.cache/ms-playwright`.
- `npm run typecheck` reads route types from `.next/types`. After moving or renaming routes, run `npx next typegen` (or a build) first, or tsc reports stale `../../app/*.js` errors.
- `cacheComponents` is on: `new Date()`, `Date.now()` and `Math.random()` while rendering (server **or** client) fail prerendering. Wrap them in a `'use cache'` function or defer with `connection()`.
- With `cacheComponents`, navigated-away routes stay mounted under `<Activity mode="hidden">`. Reset transient UI (menus, popovers) in a `useLayoutEffect` cleanup. E2E tests must use visibility-aware locators.
- `@types/node` is pinned to `^24` because Vitest 5 requires ≥22.
- From Windows tools, `mkdir -p` on the `\wsl.localhost` UNC path fails. Create directories from inside WSL (`wsl.exe ... mkdir -p`) or let the Write tool create them.
- jsdom's accessible-name computation drops the space before `sr-only` text (e.g. "Open GitHub(opens in a new tab)"). Browsers don't. Match such names in unit tests with a whitespace-tolerant regex.
- `lucide-react` 1.x has no brand icons (GitHub, LinkedIn). Use `src/components/ui/contact-icons.tsx`.
- Next's `Link` accepts `onNavigate`, but a plain `<a>` doesn't. `AppLink` routes props accordingly. Use `AppLink` for every link instead of choosing between `Link` and `<a>` yourself. It also adds the current locale to internal paths, so always pass them unprefixed (`/projects`, never `/en/projects`).
- `next start` runs the real server as a `next-server` child process, so `pkill -f "next start"` leaves it running. Stop servers by port: `fuser -k 3200/tcp`. Playwright reuses whatever is already listening on **3100** outside CI, so a leftover server makes e2e tests run against an old build. Free the port before trusting results. Don't kill the owner's `next dev`.
- Props passed from server to client components must be serializable. Content that a client component renders (e.g. pipeline stages) refers to icons by string key, mapped to Lucide components on the client.
- Content inside `Section` is wrapped in `Reveal` (Motion `whileInView`). It starts at `opacity: 0`, and the stubbed `IntersectionObserver` never fires in jsdom, so `toBeVisible()` fails in unit tests. Assert `toBeInTheDocument()` there. In Playwright, scroll sections into view before visual or axe checks (see `revealAllSections` in `e2e/home.spec.ts`).
- Some e2e expectations depend on content (e.g. hero buttons "Explore Projects" / "Get in touch", which only exist while projects and contact links are configured). If you remove content from `projects.ts` or `site-config.ts`, update `e2e/home.spec.ts` and `e2e/mobile.spec.ts` with it.
- MDX: `next.config.ts` wraps the config with `createMDX`. Add remark/rehype plugins **as strings** (`"rehype-slug"`, `["@shikijs/rehype", {...}]`) with JSON-serializable options only (Turbopack restriction). Keep `@next/mdx` pinned to the same version as `next`.
- Shiki code blocks render as `<pre class="shiki">` with per-token `--shiki-light`/`--shiki-dark` variables. Colors are chosen in `globals.css` by `data-theme`, so don't set Shiki's `defaultColor`.
- When writing files containing backticks (MD/MDX code fences) from a shell, double-quoted `bash -ic "..."` executes them as command substitution. Use the Write tool for such files.
- Don't call `python3` from the Windows-side Git Bash: it resolves to the Microsoft Store stub and hangs until the tool timeout. Use the Edit tool, `sed`, or run Python inside WSL.
- Tailwind's preflight sets `svg { display: block }`. Icons that sit inside running text (e.g. the external-link arrow in `AppLink`) need `inline` plus a vertical alignment class, or they wrap onto their own line.
- MDX case-study visuals (code themes, diagrams, tables) aren't covered by jsdom. Check them in a real build: render a throwaway `src/app/[lang]/mdx-smoke/` route, screenshot it, then delete it and run `npx next typegen`.
- Dynamic routes under Cache Components: `dynamicParams` is rejected, and `notFound()` after the shell has streamed leaves a `200`. Unknown slugs are filtered in `src/proxy.ts` before rendering, by rewriting to `UNROUTED_PATH` (`/en/__unrouted`, a path nothing serves). Never rewrite to `/404`: on Vercel that returns the not-found page with a **200**. Never rewrite to a single-segment path either: it matches `app/[lang]` as an unknown locale and renders the home page with a 200. Don't add a catch-all route that would match `UNROUTED_PATH`. To inspect Vercel routing without a token, build in a copy with a dummy `.vercel/project.json` and read `.vercel/output/config.json`. When adding another dynamic route with a known set of params, extend the proxy (and its test) rather than relying on `notFound()` alone.
- `wsl.exe -d Ubuntu -- bash -ic '...'` loses `$var` / `$!` / `$?` expansions in some invocations. A one-liner like `npm run check; echo EXIT=$?` can print `EXIT=0` after a failure, so never judge green from it: read the log for the unit-test summary (tests only run after lint, typecheck and format pass), or use a script. For anything with shell variables or loops, write a script file and run it with `bash -ic 'bash -i <file>'`. A plain `bash <file>` doesn't load nvm, so `npm` resolves to the Windows install and fails on the UNC path.
- Tests that need Node APIs (e.g. `NextRequest` for the proxy) declare `// @vitest-environment node` at the top. `vitest.setup.ts` only stubs browser globals when `window` exists.
- Shiki's `github-light` theme fails WCAG AA (orange tokens are 3.48:1 on white). Use `github-light-default`. Axe in `e2e/projects.spec.ts` checks real case-study code, so a theme change that breaks contrast fails the e2e run.
- Anything that scrolls horizontally must be focusable (axe `scrollable-region-focusable`). Wrap it in `ScrollArea` rather than a bare `overflow-x-auto` div.
- `next dev` validates instant navigation on every route and warns when `params`/`searchParams` are read outside `<Suspense>` (`instant-shell-url-data`). Keep the page component synchronous and move param-dependent work into a child inside `<Suspense>` (see `src/app/[lang]/projects/[slug]/page.tsx`). These warnings only appear in dev: check by running a separate `next dev -p 3300`, visiting the route directly and via client navigation, and reading the server log and browser console.
- `BASE_URL` switches Playwright to an existing deployment and disables its `webServer`. Keep `@smoke` tests deployment-agnostic: no content assumptions beyond what `src/content` exports, no local-only state. They run against the container, Vercel previews and production.
- The same TLS-intercepting proxy blocks Docker image pulls (Docker Hub's CloudFront and GHCR blob hosts), while manifests still resolve (`docker buildx imagetools inspect` works). On that network, `docker build`, `npm run docker:smoke` and the linter images can't run. Verify from another network or in CI. GitHub release downloads do work, so run actionlint, shellcheck and hadolint locally from their release binaries (e.g. in `/tmp`), and put shellcheck on `PATH` so actionlint checks `run:` scripts too.
- On that network `gh` can't reach `api.github.com` either. Ask the owner for CI results (or the failing log) instead of retrying.
- In `pull_request` runs, `github.sha` is GitHub's temporary merge commit, not the branch head. It's fine for PR-only artifacts. Anything published or deployed from `main` gets the real commit.
- CI pins actions by full commit SHA with a `# vX.Y.Z` comment, and linter images by digest. When adding an action, resolve the SHA with `git ls-remote https://github.com/<owner>/<repo> 'refs/tags/<tag>^{}'` (fall back to the tag ref itself for lightweight tags). Never use a moving tag.
- Docker: `.dockerignore` is an **allowlist**. A new root config the build needs (e.g. `postcss.config.mjs`) must be allowed there. The runtime stage doesn't copy `public/` because the folder doesn't exist yet; add `COPY --from=build /app/public ./public` when it does.
- The runtime image has no npm, npx, corepack or yarn: they're deleted because their bundled dependencies trip the Trivy gate. Don't use them in the runtime stage, `HEALTHCHECK` or `docker exec` checks; use `node` or busybox tools. If Trivy fails, check whether the package comes from the app (`npm ls <pkg>`, `.next/standalone/node_modules`) or from the base image before changing anything.
- Don't add the `vercel` CLI to `package.json`. It drags in many vulnerable builder packages. The pinned version lives in `.github/actions/vercel-deploy` (`cli` input) and runs via `npx`. Never re-enable Vercel Git deploys in `vercel.json`: CI is the only deployer.
- `src/content/lab-pipeline.ts` models `.github/workflows/ci.yml` for the Lab, and `lab-pipeline.drift.test.ts` fails when they diverge. When you change jobs, `needs`, `if:` conditions or step names in `ci.yml`, update the model in the same change. A new `if:` expression also needs an entry in the test's `CONDITIONS` table. Excerpts quote `ci.yml` verbatim (trimmed, with `# …` for gaps) and must never contain pinned SHAs or digests.
- Keep the Dockerfile's `FROM` lines literal (`node:24-alpine@sha256:…` in each stage). Dependabot can't update a base image behind `FROM ${ARG}`. Validate `.github/*.yml` against SchemaStore with `check-jsonschema --builtin-schema vendor.dependabot|vendor.github-workflows|vendor.github-actions` (install it into a venv in WSL).
- `output: "standalone"` is enabled only with `BUILD_STANDALONE=1` (Dockerfile). Don't make it unconditional: `next start` (Playwright's server) doesn't support it.
- Every `page.tsx` sets `alternates: canonicalFor("<its unprefixed path>", locale)` (`src/lib/canonical.ts`), which emits the canonical in the page's language plus `hreflang` alternates. Never set alternates in a layout: metadata merges shallowly, so child pages would inherit them. Locally there's no `NEXT_PUBLIC_SITE_URL` and neither is emitted. A new page also needs adding to `sitemapEntries` (`src/lib/sitemap.ts`) unless it comes from an enabled route, a case study or a Lab demo. To test canonicals and `hreflang`, build with `NEXT_PUBLIC_SITE_URL=https://example.test` and run the `@smoke` suite against `next start` via `BASE_URL`.
- The Pipeline Explorer has two interaction modes. From `lg` (64rem) up it's a tablist (`role="tab"`, panel below, Previous/Next). Below that it's an accordion (buttons with `aria-expanded`, a `region` under the open job, no Previous/Next). E2E tests must pick roles per project (`mobile-chromium` is narrow), and unit tests choose the mode with `stubMatchMedia` from `src/test/match-media.ts`. jsdom answers every media query with `false`, i.e. narrow and no reduced motion.
- Testing timer-driven UI (e.g. the Pipeline Explorer's Run playback):
  - The next `setTimeout` is only scheduled after React commits the previous frame. With Vitest fake timers, advance one tick per `act(...)` (see `tick()` in `pipeline-explorer.test.tsx`). One big `advanceTimersByTime` inside a single `act` fires only one frame. With Playwright's `page.clock`, `runFor` one tick and wait for the result before the next.
  - `userEvent` hangs under `vi.useFakeTimers()`. Use `fireEvent` inside `act` there.
  - `page.clock.install()` also freezes `requestAnimationFrame`, so Motion fades stay at `opacity: 0`. Don't take screenshots or run axe on a clock-controlled page.
- `TILE_SURFACES` in `src/lib/tech-icons.ts` duplicates `--surface-elevated` from `globals.css` so brand colours can be contrast-checked at render time. `tokens.test.ts` fails if they drift; update both together. Brand colours below 3:1 on the tile fall back to `--foreground` per theme.
- `Tooltip` shows its content purely through CSS `group-hover`/`group-focus-within` and positions it against the nearest `relative` ancestor (the skill card's `ul`). Without such an ancestor it spans the page. It hides with `visibility: hidden` + `opacity: 0` (not `display: none`, which can't fade), so it can't catch the pointer while hidden and is still the trigger's accessible description; assert with `toHaveAccessibleDescription` in unit tests and visibility only in Playwright.
- Routes live under `src/app/[lang]` (the root layout is there; `src/app/` only holds `globals.css`, `tokens.test.ts`, `global-not-found.tsx` and `sitemap.ts`). The proxy rewrites unprefixed English URLs to `/en/...` and 308s a typed `/en/...` back, except metadata image URLs (`opengraph-image`, `icon`), which Next itself links with the `/en` prefix. A new route needs no proxy change, but `PageProps`/`LayoutProps` take the internal path (`PageProps<"/[lang]/projects/[slug]">`), and a metadata image file at a level without its own dynamic segment needs `generateStaticParams` over `locales`, or it becomes dynamic.
- `usePathname()` returns the internal `/en/...` path on prerendered pages (even after hydration) but the public path after client navigation. Compare paths with `stripLocale` from `src/i18n/locales.ts`.
- `NavLink` sets `aria-current="page"` on exact matches and `"true"` on child pages of its section. E2E tests asserting nav state must pick the right value.
- `next/root-params` (`getLocale()`) doesn't work in metadata image routes (`opengraph-image.tsx`, `icon.tsx`), which are route handlers. Read `(await params).lang` there and narrow it with `toLocale`. For a translated `alt`, OG images use `generateImageMetadata` (whose `params` is a plain object, not a promise). That moves the image to `.../opengraph-image/<id>`, so the proxy's `METADATA_IMAGE` pattern allows one trailing segment; keep it in sync if image URLs change.
- `localize` treats any object whose keys are exactly the locales as a `Localized` text. Don't give content data an object shaped like `{ en: ... }` for any other purpose.
- Messages may be functions (for interpolation), so a server component must never pass a `Messages` object, or part of one, as a prop to a client component: functions aren't serializable. Client components read `useMessages()` themselves.
- MDX case-study components that need text (`Callout`, `Diagram`, the table wrapper) get the locale through `getMdxComponents(locale)`, which the case-study page passes as `<Body components={...} />`. `useMDXComponents()` only serves the default locale for `@next/mdx`.
- Locales are `en` (unprefixed) and `pt-br` (prefixed, English path segments: `/pt-br/projects`). Adding a `Localized` field or a message without a `"pt-br"` value fails typecheck; leaving it identical to English fails `translations.test.ts` unless the text is in its `SAME_IN_BOTH` allowlist. Mark drafted translations `TODO(content)`.
- An icon-like link whose visible text differs from its `aria-label` fails axe `label-content-name-mismatch` (WCAG 2.5.3). Start the label with the visible text, as `LanguageSwitch` does ("PT — Ver em português").
- E2E tests that press keys on tabs or radios must `await waitForHydration(page)` (`e2e/hydration.ts`) after `goto`; under parallel load, keys pressed before hydration are lost and the test flakes. The helper matches the theme toggle's mounted label in both languages.
- Unmatched URLs render `global-not-found.tsx`, which is outside `[lang]`, so a Portuguese 404 (`/pt-br/nope`, unknown `/pt-br/projects/<slug>`) shows the English page. Known limitation, kept on purpose. Tried and rejected: (1) a page or catch-all that calls `notFound()` answers 404, but under Cache Components its body is a client-only `__next_error__` shell (blank without JavaScript), even with a segment `not-found.tsx` and with `globalNotFound` off; (2) a proxy rewrite to a page that renders `NotFoundView` ignores `NextResponse.rewrite(url, { status: 404 })` and answers 200. The remaining option, the proxy returning the fetched page itself with a 404, was declined because it needs a known-routes list.
- Case studies have one MDX file per language (`<name>.mdx`, `<name>.pt-br.mdx`), chosen by `caseStudyFile`. Change both when editing a case study; `case-studies.test.ts` fails if one is missing. Heading ids come from the translated headings (`#visão-geral`), so never link to a case-study anchor across languages. Translated `Diagram` labels can outgrow the 150-unit boxes: after changing labels, check them in a real build (see the MDX smoke-route gotcha).
